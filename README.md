# 🔍 Скидочный сыщик (DiscountFinder)

**Скидочный сыщик** — полнофункциональное приложение для поиска и отслеживания цен на маркетплейсах. Ищи товары, добавляй в избранное, следи за историей цен — приложение покажет, когда товар подешевел.

## 🧩 Как это работает (простым языком)

Представь себе два отдельных приложения, которые общаются между собой:

```
┌─────────────┐     HTTP-запросы      ┌──────────────┐      SQL       ┌────────────┐
│  FRONTEND   │ ◄──────────────────►  │   BACKEND    │ ◄───────────►  │  POSTGRES  │
│  (Flet GUI) │   (JSON туда-сюда)    │  (FastAPI)   │  (сохранение)  │    (БД)    │
└─────────────┘                       └──────┬───────┘                └────────────┘
                                             │
                                     subprocess (отдельный процесс)
                                             │
                                     ┌───────▼───────┐
                                     │   ПАРСЕР      │
                                     │  (Playwright) │
                                     └───────────────┘
```

1. **Ты открываешь приложение** → видишь форму входа.
2. **Регистрируешься / входишь** → frontend отправляет email и пароль на backend, получает JWT-токен.
3. **Ищешь товар** (например, «наушники») → frontend отправляет запрос на backend → backend запускает парсер → парсер открывает настоящий браузер (Chromium), заходит на Яндекс Маркет, скроллит страницу, собирает карточки товаров → отдаёт JSON обратно → backend возвращает данные → frontend рисует карточки.
4. **Добавляешь товар в избранное** → backend сохраняет его в базу данных вместе с текущей ценой.
5. **Заходишь в «Мой список»** → видишь все избранные товары + историю цен (когда подешевело, когда подорожало).

## 🛠 Технологии и зачем они нужны

### Backend (серверная часть)

| Технология | Зачем нужна |
|---|---|
| **Python** | Основной язык всего проекта |
| **FastAPI** | Веб-фреймворк для создания API. Быстрый, поддерживает асинхронность (обрабатывает несколько запросов одновременно), автоматически генерирует документацию API |
| **SQLAlchemy** | ORM — позволяет работать с базой данных через Python-объекты, а не писать SQL-запросы вручную. Ты пишешь `db.query(Product).all()` вместо `SELECT * FROM products` |

| **python-dotenv** | Загрузка секретных настроек (пароли от БД, секретные ключи) из `.env` файла, чтобы не хардкодить их в коде |
| **Uvicorn** | ASGI-сервер — запускает FastAPI-приложение и обрабатывает HTTP-запросы |

## 📋 Что делает каждый файл

### Backend

#### `backend/main.py` — Точка входа API
Это «мозг» сервера. Здесь:
- Создаётся FastAPI-приложение
- Описаны все API-эндпоинты (маршруты):
  - `POST /auth/register` — регистрация нового пользователя
  - `POST /auth/login` — вход (возвращает JWT-токен)
  - `GET /search?q=...` — поиск товаров на маркетплейсах
  - `GET /favorites` — получить список избранных товаров
  - `POST /favorites` — добавить товар в избранное
  - `DELETE /favorites/{id}` — удалить товар из избранного
- При старте сервера создаются таблицы в БД и запускается фоновый мониторинг цен
- Функция `normalize_url` — очищает URL от параметров (подробнее ниже)

#### `backend/database.py` — Подключение к БД
- Читает `DATABASE_URL` из `.env` файла
- Создаёт «движок» (`engine`) для общения с PostgreSQL
- Предоставляет `SessionLocal` — фабрику сессий (каждый запрос к API = своя сессия)
- Содержит `get_db()` — dependency для FastAPI (автоматически открывает и закрывает сессию)

#### `backend/models.py` — Модели базы данных
Описывает таблицы БД в виде Python-классов:
- **User** — пользователь (email + захешированный пароль)
- **Product** — товар в избранном (название, цена, URL, картинка, маркетплейс, рейтинг)
- **PriceHistory** — запись об изменении цены (цена + дата проверки)

Связи:
```
User (1) ──► (∞) Product (1) ──► (∞) PriceHistory
Один юзер      Много товаров      Много записей цен
```

#### `backend/schemas.py` — Pydantic-схемы
Определяет «формат» данных для API:
- **UserCreate** — что нужно для регистрации (email + пароль)
- **UserOut** — что API возвращает о пользователе (id + email, без пароля!)
- **Token** — формат JWT-токена
- **ProductCreate** — данные для добавления товара в избранное
- **ProductOut** — полная информация о товаре (включая историю цен)
- **SearchResult** — один результат поиска
- **PriceHistoryOut** — одна запись истории цены

#### `backend/auth.py` — Авторизация
- `hash_password()` — превращает пароль в хеш (алгоритм sha256_crypt)
- `verify_password()` — проверяет, совпадает ли введённый пароль с хешем
- `create_access_token()` — создаёт JWT-токен со сроком действия 24 часа
- `get_current_user()` — dependency для FastAPI: вытаскивает токен из заголовка `Authorization`, проверяет его, находит пользователя в БД

#### `backend/services.py` — Бизнес-логика
- **ParserService** — класс-агрегатор парсеров:
  - `search_wildberries()` — заглушка (пока не реализован)
  - `search_ozon()` — заглушка (пока не реализован)
  - `search_yandex()` — запускает парсер в отдельном процессе, получает JSON из stdout
  - `search_all()` — вызывает все парсеры параллельно и объединяет результаты
- **price_monitor_loop()** — фоновая задача, раз в 30 минут немного меняет цены избранных товаров (симуляция обновления)
- **`_clean_price()`** — очищает строку цены («1 299 ₽» → `1299.0`)

#### `backend/parsers.py` — Парсер Яндекс Маркета
Этот файл запускается как **отдельный процесс** (`python -m backend.parsers "запрос"`).
- Открывает headless-браузер Chromium через Playwright
- Переходит на страницу поиска Яндекс Маркета
- Ждёт загрузки, скроллит страницу вниз (чтобы подгрузились все товары)
- Для каждой карточки товара находит: название, цену, старую цену, ссылку, картинку, рейтинг
- Выводит результат в виде JSON в stdout

### Поток авторизации
```
Пользователь вводит email/пароль
         │
         ▼
  Frontend (auth.py)

         │
         ▼
  Backend (main.py → login)
  Ищет пользователя в БД → проверяет пароль → создаёт JWT
         │
         ▼
  Frontend получает токен
  token_ref["value"] = "eyJhbG..."
  Все дальнейшие запросы идут с заголовком:
  Authorization: Bearer eyJhbG...
```

### Поток поиска
```
Пользователь вводит "наушники" → нажимает "Найти"
         │
         ▼
  Frontend (home.py → do_search)
  api("GET", "/search?q=наушники", token=...)
         │
         ▼
  Backend (main.py → search)
  Вызывает parser.search_all("наушники")
         │
         ▼
  Services (services.py → search_yandex)
  subprocess.run(["python", "-m", "backend.parsers", "наушники"])
         │
         ▼
  Parsers (parsers.py)
  Playwright открывает Chromium → идёт на market.yandex.ru
  → скроллит → собирает карточки → print(json.dumps(results))
         │
         ▼
  Services ловит stdout → парсит JSON → возвращает [SearchResult, ...]
         │
         ▼
  Backend: если товар уже в избранном — обновляет цену + пишет историю
  Возвращает JSON-массив результатов
         │
         ▼
  Frontend: рисует карточки товаров в GridView
```

### Поток добавления в избранное
```
Клик на ★ "В избранное"
         │
         ▼

  api("POST", "/favorites", json={title, price, url, ...})
         │
         ▼
  Backend (main.py → add_favorite)
  Проверяет: такого URL нет? → Создаёт Product + PriceHistory → commit
         │
         ▼
  Frontend: кнопка меняется на "В избранном ✓"
```

## 🚀 Установка и запуск

### Требования
- Python 3.10+
- PostgreSQL (установленный и запущенный)

### 1. Клонирование и настройка окружения
```bash
git clone <url-репозитория>
cd DiscountFinder

# Создаём виртуальное окружение
python -m venv venv

# Активируем (Windows)
venv\Scripts\activate

# Устанавливаем зависимости
pip install -r requirements.txt
```

### 2. Установка браузера для парсера
```bash
playwright install chromium
```

### 3. Настройка базы данных
1. Создай базу данных в PostgreSQL:
```sql
CREATE DATABASE discount_db;
```
2. Скопируй `.env.example` в `.env` и заполни:
```
DATABASE_URL=postgresql://логин:пароль@localhost:5432/discount_db
SECRET_KEY=любая-длинная-секретная-строка
```

### 4. Запуск

**Сначала** запусти backend (из корня проекта):
```bash
uvicorn backend.main:app --reload
```
Сервер стартанёт на `http://127.0.0.1:8000`. Swagger-документация доступна на `http://127.0.0.1:8000/docs`.

**Затем** запусти frontend (в новом терминале):
```bash
python frontend/app.py
```

## 🧠 Технические решения

### Проблема с asyncio на Windows
**Проблема**: Playwright управляет браузером через подпроцессы. На Windows стандартный event loop (`SelectorEventLoop`) не поддерживает подпроцессы, что вызывает `NotImplementedError`.

**Решение**: Парсер запускается в **полностью отдельном процессе** через `subprocess.run()`. Backend вызывает `python -m backend.parsers "запрос"` и читает результат из stdout. Это изолирует браузер от цикла событий сервера.

### Нормализация URL
**Проблема**: Яндекс Маркет добавляет к ссылкам параметры трекинга (`?lr=213&clid=...`), которые меняются от поиска к поиску. Без нормализации один и тот же товар каждый раз выглядит как новый.

**Решение**: Функция `normalize_url()` отрезает всё после `?` и убирает слеш в конце. Сравнение идёт по «чистому» URL карточки товара.

### Кодировка UTF-8 на Windows
**Проблема**: При передаче кириллических данных через subprocess на Windows возникает `UnicodeEncodeError`.

**Решение**: В парсере принудительно переключаем stdout на UTF-8: `sys.stdout.reconfigure(encoding='utf-8')`.

---

> **Примечание**: Парсеры для Wildberries и Ozon — заглушки (возвращают пустой список). Архитектура `ParserService` позволяет легко добавить их по аналогии с `search_yandex()`.
