# 🛒 Проект: Скидочный сыщик (Discount Finder)

**Скидочный сыщик** — это полнофункциональное Fullstack-приложение для автоматизированного поиска и мониторинга цен на маркетплейсах. Система позволяет пользователям отслеживать динамику цен в реальном времени, визуализировать историю изменений и оперативно реагировать на скидки.

---

## 🏛 Архитектура системы

Проект построен на базе **микросервисной архитектуры** (разделение Frontend и Backend), что обеспечивает масштабируемость и независимую разработку компонентов.

### **1. Backend (FastAPI + SQLAlchemy)**
Выбран **FastAPI**, так как это один из самых быстрых Python-фреймворков, поддерживающий асинхронность (`asyncio`) «из коробки».
*   **Слой данных (Database)**: Используется **SQLite** с ORM **SQLAlchemy**. Архитектура БД спроектирована с учетом связей «Один ко многим» (Один пользователь -> Много товаров; Один товар -> Много записей истории цен).
*   **Безопасность (Auth)**: Реализована аутентификация на базе **JWT (JSON Web Tokens)**. Пароли хранятся в хешированном виде (библиотека `passlib` с алгоритмом `bcrypt`), что исключает их утечку в открытом виде.
*   **Слой парсинга**: Интеграция с **Playwright**. Это мощный инструмент автоматизации браузера, который, в отличие от простых библиотек (типа `requests`), позволяет обходить защиту маркетплейсов, исполнять JavaScript и имитировать поведение реального пользователя.

### **2. Frontend (Flet)**
Выбран **Flet** (на базе **Flutter**), что позволило создать современный реактивный интерфейс на Python. 
*   **UI/UX**: Использована темная тема (GitHub-style) с акцентными цветами. Сетка товаров адаптивная (`GridView`), карточки имеют фиксированную высоту для сохранения визуальной целостности интерфейса.
*   **State Management**: Состояние приложения (токены, результаты поиска) управляется через ссылки (`refs`) и события страницы, обеспечивая мгновенную реакцию интерфейса на действия пользователя.

## 🔬 Глубокая техническая реализация (Key Features)

### **🚀 Решение проблемы "Windows asyncio loop"**
**Проблема**: При работе Playwright внутри FastAPI на Windows часто возникает ошибка `NotImplementedError`. Это связано с тем, что стандартный цикл событий (`SelectorEventLoop`) в Windows не поддерживает подпроцессы браузера.
**Решение**: Я реализовал запуск парсера через **отдельный процесс** (`subprocess.run`). Это изолирует браузер от основного цикла событий сервера, делая систему максимально стабильной и кроссплатформенной.

### **🔗 Умная нормализация URL (Matching Logic)**
**Проблема**: Маркетплейсы добавляют в ссылки уникальные ID сессий и токены отслеживания (параметры после `?`). Прямое сравнение ссылок `url1 == url2` всегда выдавало бы «ложно», и история цен не привязывалась бы к товару.
**Решение**: Создана функция `normalize_url`, которая отсекает технические параметры. Сравнение идет по «чистому» адресу карточки товара. Это гарантирует, что система «узнает» ваш товар, даже если Яндекс изменил рекламную метку в ссылке.

### **📉 Алгоритм расчета трендов**
В разделе «Мой список» реализован алгоритм анализа истории:
1. Система берет массив цен из БД.
2. Итерируется по нему, сравнивая каждую точку с предыдущей.
3. Вычисляет дельту (разницу) в рублях и процентах.
4. Динамически отрисовывает индикаторы: **зеленый (скидка)** или **красный (подорожание)**.

### **🔡 Решение проблем с кодировкой (UTF-8 на Windows)**
**Проблема**: При передаче данных от парсера к бэкенду на Windows возникали ошибки `UnicodeEncodeError` из-за специфических символов в названиях товаров.
**Решение**: В парсере принудительно настроена переконфигурация стандартного вывода: `sys.stdout.reconfigure(encoding='utf-8')`. Это обеспечивает корректную передачу любых кириллических и спецсимволов.

## 📂 Описание модулей

### **Backend**
*   `main.py`: Маршрутизация, управление сессиями БД, логика фоновых задач.
*   `parsers.py`: Скрипт-парсер. Содержит логику имитации скроллинга страницы и селекторы для поиска элементов (заголовки, цены по атрибутам `data-auto`).
*   `models.py`: Схемы таблиц (User, Product, PriceHistory).
*   `schemas.py`: DTO-объекты для обмена данными (валидация входных JSON).

### **Frontend**
*   `app.py`: Вся логика UI. Включает кастомные виджеты (карточки, кнопки, строки истории) и логику асинхронных запросов к API через `httpx`.

## 🛠 Инструкция по развертыванию

1. **Окружение**:
   ```bash
   python -m venv venv
   source venv/bin/activate  # или venv\Scripts\activate на Win
   pip install -r requirements.txt
   ```
2. **Браузер**:
   ```bash
   playwright install chromium
   ```
3. **Запуск**:
   Сначала бэкенд: `uvicorn backend.main:app --reload`
   Затем клиент: `python frontend/app.py`
